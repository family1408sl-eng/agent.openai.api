## 1. Назначение

Помощник по OpenAI API нужен для направления: OpenAI API, SDK и интеграции: разработка, модели, стоимость, лимиты и диагностика.

Первая предметная цель: выбрать и затем по отдельному поручению реализовать личную автоматизацию работы с документами и юридическими задачами, используя существующие проекты `agent.*`. Рассматриваются закрытый кабинет, почтовый диспетчер и распределение поручений между агентами с понятным контролем расходов.

Кандидаты: локальный обработчик с Codex по Pro, отдельное приложение через OpenAI API, гибрид. Полный переход на API и окончательная архитектура не выбраны. Возможный первый сценарий: тестовое письмо с договором → подготовка → анализ по методике пользователя → таблица замечаний → результат пользователю.

Исходные данные и ограничения: [docs/PROJECT_CONTEXT.md](docs/PROJECT_CONTEXT.md). Полная передача: [2026-10-29-pro200-api-handoff.md](docs/context/2026-10-29-pro200-api-handoff.md).

По переданному контексту на 2026-10-29, основанному на прежнем обсуждении и ранее показанных скриншотах: действует Pro 200; личная API-организация уже существует, пользователь — Owner; привязка бонуса завершена; грант $19 доступен полностью, расход $0, на экране указано истечение 2026-11-01 без точного времени и часового пояса. При импорте эти экраны и текущий кабинет не проверялись.

На 2026-11-01 показано следующее продление подписки. Отдельный грант $200 только ожидается при сохранении условий и успешном продлении; его зачисление не подтверждено. Не использовать исторический баланс как текущий и не повторять завершённую активацию.

Создание рабочего API-ключа, первый успешный API-вызов, развёртывание сайта и почтового диспетчера в переданном обсуждении не подтверждены. Старый экран Limits относится к состоянию до начисления и не доказывает текущий доступ.

- Локальный проект плюс глобальная personal custom-agent роль.
- Модель роли: `gpt-6.1-sol`; reasoning effort: `high`; декларация sandbox: `workspace-write`, без расширения фактических прав родительского сеанса.
- Канонический TOML: `E:\Codex\agent.openai.api\codex-agent\agent.openai.api.toml`.
- Установленный TOML: `C:\Users\Сергей\.codex\agents\agent.openai.api.toml`.
- Облачная среда не создается. Модель, вызываемая будущим API-кодом, определяется отдельно по задаче и доступам, не выводится автоматически из модели роли.

## Предметная работа и безопасность

Помощь с API-клиентами и SDK, контрактами запросов/ответов, инструментами, streaming, файлами, диагностикой, тестированием, учетом использования и стоимостью. Текущие сведения проверяются по официальной OpenAI документации с датой и ссылками. Установка профиля не подтверждает доступ API-аккаунта или фактический вызов модели.

Ключи, токены, приватные payloads и непубличные данные аккаунта не попадают в GitHub, Wiki, память и handoff. Непубличные данные хранятся только в `workspace/private_artifacts/`; секреты не сохраняются в документах и логах. Сначала offline fixtures/mocks. Платные API-запросы, реальные загрузки файлов, удаление ресурсов, настройки биллинга и доступа требуют отдельного поручения с конкретным объемом. В onboarding ключи и live API не используются.

Публичная версия исходного состояния в `docs/PROJECT_CONTEXT.md` и датированной передаче сохранена по прямому поручению пользователя на этот импорт: контактный адрес и отображаемое учётное имя удалены, точные идентификаторы и секреты не включены. Это разрешение ограничено подготовленным контекстом и не разрешает публикацию дополнительных данных аккаунта.

Чужие проекты по умолчанию read-only. Свои файлы и память можно обогащать по явному поручению владельца через установленный workflow. Конкретная чужая запись требует подтверждения действия и пути; профиль не обходит песочницу.

## 3. Правила работы

- Значимые решения фиксируются в локальных документах или Wiki.
- `запиши` создает или обновляет рабочие Wiki-страницы через `agent.wiki`.
- `запомни` создает заявку на долговременную память через outbox и `memory-server-process`.
- Если в подтвержденном onboarding указан GitHub-репозиторий, первый commit и push в `origin/main` обязательны до завершения создания агента.
- В первую публикацию входят все неигнорируемые локальные файлы; `.agent-memory`, private/raw-артефакты и секреты не публикуются.
- После первоначальной публикации Git commit выполняется только по команде `фиксируй`, а push - по команде `актуализируй GitHub`.
